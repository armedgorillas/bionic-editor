# Development Plan

## Guiding Principles & Architectural Constraints

All improvements in this plan must preserve Bionic Editor's core product and deployment invariants:

1. **Non-Coder First, Progressive Disclosure**: Analytical scientists should see a calm, document-centric workspace by default. Developer concepts (dotfiles, source code trees, agent prompts, JSON manifests, subagent traces) remain tucked behind opt-in controls or **Coding Mode**.
2. **Single-Port + `BASE_URL` Slug Compatibility**: Every new HTTP endpoint must mount on `apiRouter` in `server/index.ts` (automatically served at both `/api/*` and `${BASE_URL}/api/*`), and all client requests/asset URLs (including WYSIWYG inline images) must use `API_BASE` from `client/src/services/api.ts`.
3. **Linux Multi-User / Systemd Ownership**: Any server-written files or created directories (`.opencode/`, `.bionic/`, `data/manifest.json`, `.gitignore`, multer uploads, sessions) must apply `TARGET_USER` ownership **recursively** across newly created ancestor directories so agent and coding-mode processes running as `SERVICE_USER` retain read/write permissions.
4. **OpenCode V2 Primary Harness + Honest Fallback Behavior**: Features touching agent behavior must work reliably with OpenCode V2 (`opencode run --format json`, `.opencode/opencode.jsonc`, `.opencode/agents/*.md`, `instructions`) and degrade cleanly when running on built-in OpenAI/Gemini/Anthropic/Demo fallback runners.
5. **Non-Destructive Workspace Hygiene**: Never mutate an arbitrary workspace directory merely on server startup; write managed Bionic/OpenCode config files only during explicit template initialization (`initDefaultTemplate()`) or lazily when an agent run begins.

## Phase 0: Pre-Requisite Stability, Security & OpenCode Fixes

Before building Features 1–6, fix five existing codebase issues that would otherwise cause regressions or silent failures across multiple features:

1. **Decouple File-Tree Refresh from Session Loading (`client/src/App.tsx`)**:
   - Currently, WebSocket `file_changed` events call `loadWorkspace()`, which reloads the persisted session from disk and calls `setMessages(sessionData.messages)` — wiping active streaming chat state whenever the agent writes a `.md` or manifest file mid-turn.
   - **Fix**: Split `loadWorkspace()` into `initializeWorkspace()` (runs once on mount; loads sessions, server keys, and `harness`/`isOpenCodeInstalled`) and `refreshWorkspaceFiles()` (called on `file_changed` and file CRUD; refreshes `fileTree` and `venvStatus` only). Also sync `openai` and `anthropic` flags in `serverKeys` on save, and type `isOpenCodeInstalled` / `harness` in `client/src/services/api.ts`.
2. **Guard WYSIWYG Autosave & Fix `BASE_URL` Inline Images (`client/src/App.tsx`, `client/src/components/Editor/WysiwygEditor.tsx`, `server/index.ts`)**:
   - Guard external file reloads (`file_changed` and `handleSendMessage` `finally`) so active typing (`saveStatus !== 'saved'`) and self-writes are never overwritten by stale `chokidar` events.
   - Replace hardcoded `/api/files/raw/` in `WysiwygEditor.tsx`'s `CustomImage` extension with `${API_BASE}/files/raw/` so embedded figures work behind a `BASE_URL` slug.
   - URL-decode `req.path` (`decodeURIComponent`) and verify `stat.isFile()` in `apiRouter.use('/files/raw', ...)` (`server/index.ts`) so filenames with spaces load cleanly.
3. **Fix Double `final` SSE Event & OpenCode `text` Duplication (`server/index.ts`, `server/services/agent.ts`)**:
   - Currently both `agent.ts` runners and `server/index.ts` emit `type: 'final'`, causing `App.tsx` to double-count token usage and USD cost on every turn. Emit `final` in exactly one place (`server/index.ts`).
   - In `runOpenCodeAgent()`, stop emitting final assistant `text` blocks as both `thought` and `final` (route thinking blocks separately from final narrative text).
4. **OpenCode V2 Persistent Server Bridge (`server/services/opencodeServer.ts`, `server/services/agent.ts`)**:
   - Currently, `agent.ts` spawns a one-shot `opencode run --format json` subprocess per HTTP request. In OpenCode V2, this causes three major bugs:
     1. **Background subagents vanish**: OpenCode V2 subagents always run in the background and report back to the parent session when idle. When the one-shot `opencode run` exits and the SSE HTTP stream closes, the sidebar chat **never receives the update** when the subagent finishes.
     2. **API keys & cancellation break**: Without `--standalone`, `opencode run` talks to a shared user daemon that ignores per-spawn `extraEnv` API keys, and `SIGKILL` on the CLI client does not reliably abort server-side execution or background child subagents. (Conversely, `--standalone` kills its private server on exit, aborting any running background subagent!)
     3. **Unreliable event separation**: CLI stdout parsing mixes reasoning, text, and tool events.
   - **Fix**: Replace one-shot `opencode run` with a **Bionic-managed private `opencode serve` process** bound to `127.0.0.1` on an internal port (never exposed externally—single-port invariant preserved!), controlled via `@opencode/client` (or direct HTTP/SSE to `127.0.0.1:<internal-port>`):
     - Start lazily on first OpenCode request, shut down cleanly on Bionic server exit, and pass `getTargetSpawnOptions()` + configured API keys (plus `PUT /api/session/{id}/environment` or `POST /api/credential` when keys update in Settings).
     - Subscribe to `GET /api/event` (`client.event.subscribe()`) and multiplex live session & background job updates (`experimental.job.updated`, `session.text.delta`, `session.tool.*`, `session.idle`, etc.) to connected browsers over Bionic's existing `/ws` WebSocket.
     - Cancel active runs cleanly via `POST /api/session/{id}/interrupt` and cancel running subagents via `POST /api/experimental/job/{id}/cancel`.
     - Resync missed background completions on reconnect/reload via `GET /api/session/{id}/message`.
     - *(Fallback if `opencode` is absent)*: Built-in OpenAI/Gemini/Anthropic/Demo runners continue working unchanged.
5. **Filesystem, Symlink & Watcher Hardening (`server/services/workspace.ts`, `server/services/fileWatcher.ts`, `server/index.ts`, `server/services/sessionManager.ts`)**:
   - Add `ensureDirWithOwnership()` to chown every newly created parent directory (fixing non-recursive `applyTargetOwnership()` and `BASE_SPEC` in subdirectories like `notes/protocol.md`). Apply ownership to `multer` uploads (and sanitize upload filenames via `path.basename()`) and `sessionManager.ts`.
   - Harden `resolveSafePath()` with `fs.realpathSync()` on the path (or closest existing ancestor) to block symlink escapes outside `WORKSPACE_DIR`.
   - Use `fs.lstatSync()` wrapped in `try/catch` in `getFileTree()` so broken symlinks do not crash tree loading.
   - Replace the blanket dotfile regex `/(^|[\/\\])\../` in `server/services/fileWatcher.ts` with an explicit ignore list (`**/.venv/**`, `**/.git/**`, `**/node_modules/**`, `**/__pycache__/**`, `**/.bionic/sessions/**`, `**/.pytest_cache/**`) so `.opencode/`, `.gitignore`, and `.bionic/*.md` remain observable while chat saves don't trigger noisy refreshes.

## Feature 1: Theme Skins & Dark Mode

### Current State
- `client/tailwind.config.js` (Tailwind CSS `3.4.19`) does not enable `darkMode: 'class'`.
- `client/src/index.css` hardcodes light colors (`#fbfbfb`, `#2b303a`) and TipTap `.tiptap` styles.
- Components (`App.tsx`, `FileExplorer.tsx`, `WysiwygEditor.tsx`, `AgentPanel.tsx`, `MarkdownMessage.tsx`, `ReportViewer.tsx`, `SettingsModal.tsx`, `HelpModal.tsx`) use hardcoded light Tailwind classes and pastel badges (`bg-amber-50`, `bg-emerald-50`, `bg-indigo-50/70`, `bg-orange-50`).
- `MonacoViewer.tsx` is hardcoded to `theme="vs-dark"`; `TerminalPanel.tsx` is always dark `#181818`.

### Design & UX
- **Semantic RGB-Channel Token + Skin Architecture**: Store semantic tokens as space-separated RGB channels (`--bg-surface: 15 17 23;`) scoped to `data-theme` on `<html>`, mapped in Tailwind v3 via `rgb(var(--bg-surface) / <alpha-value>)` alongside `darkMode: 'class'`. This preserves Tailwind v3 opacity modifiers (`bg-surface/95`, `border-edge/80`) while making new skins a single CSS token block.
- **Built-in Themes / Skins**:
  - `system`: Follows `window.matchMedia('(prefers-color-scheme: dark)')`.
  - `light` (**Lab Paper** — default): Crisp white editor canvas, soft gray chrome, subtle blue accents.
  - `dark` (**Midnight Lab**): Low-glare charcoal/slate surfaces (`#0f1117` canvas, `#161a23` panels, `#262c3a` borders, warm off-white reading typography).
  - `warm` (**Warm Notebook** — included light skin): Soft cream paper (`#faf7f2`) for long-form scientific reading.
- **Controls**:
  - Quick light/dark toggle button (Sun/Moon icon) in the top header (`client/src/App.tsx`).
  - Full **Appearance** selector inside a refactored tabbed `SettingsModal.tsx`.
- **Iframe Isolation (`ReportViewer.tsx`)**: Theme only the `ReportViewer` toolbar and frame; never force-invert user/agent-generated `web-report/index.html` content so custom scientific palettes remain intact.

### Implementation Plan
1. **FOUC Prevention** — `client/index.html`:
   - Add a tiny synchronous inline `<script>` in `<head>` wrapped in `try { ... } catch {}` (safe in sandboxed/private iframes) that reads `localStorage.getItem('bionic_theme')`, resolves `'system'`, sets `document.documentElement.dataset.theme`, and toggles `.dark` before React mounts.
2. **Theme Context** — `client/src/contexts/ThemeContext.tsx` (new):
   - Manage `themePreference` (`'system' | 'light' | 'dark' | 'warm'`) and `resolvedMode` (`'light' | 'dark'`).
   - Listen to `prefers-color-scheme` changes when `'system'` is active; persist in `localStorage` (`bionic_theme`).
   - Keep `MarkdownMessage.tsx` SSR-safe (relying on Tailwind `dark:` classes and CSS variables rather than reading `window` or requiring a non-null context) so `tests/issues-6-7-8.test.mjs` (`renderToStaticMarkup`) continues to pass.
3. **Tailwind & CSS Tokens** — `client/tailwind.config.js`, `client/src/index.css`:
   - Enable `darkMode: 'class'` and map semantic tokens (`surface`, `panel`, `elevated`, `edge`, `ink`, `muted`, `accent`) using `rgb(var(--...) / <alpha-value>)`.
   - Migrate `.tiptap` rules in `client/src/index.css` (headings, text, blockquotes, inline code, pre blocks, tables, borders, selection highlight) to CSS variables for `:root`, `[data-theme="dark"]`, and `[data-theme="warm"]`.
4. **Tabbed `SettingsModal.tsx` & Component Audit**:
   - Refactor `SettingsModal.tsx` from `max-w-md` into a clean tabbed modal (`max-w-2xl`, matching `HelpModal.tsx`): **Workspace** (Project Root File, Feature 7), **Appearance** (Feature 1), **AI & Models**, and **Agent Instructions** (Feature 5).
   - Audit all components (`App.tsx`, `FileExplorer.tsx`, `WysiwygEditor.tsx`, `MonacoViewer.tsx`, `AgentPanel.tsx`, `MarkdownMessage.tsx`, `ReportViewer.tsx`, `SettingsModal.tsx`, `HelpModal.tsx`), including dark variants for all pastel status badges (`amber`, `emerald`, `indigo`, `orange`, `red`).
   - Sync `MonacoViewer.tsx` `theme` prop to `resolvedMode === 'dark' ? 'vs-dark' : 'vs'`.

### Acceptance Criteria & Testing
- Reloading in Dark Mode exhibits zero white flash and does not throw in restricted storage environments.
- Body and badge contrast meet WCAG AA (>= 4.5:1) across Light, Dark, and Warm themes.

## Feature 3: Exposing OpenCode Subagents Cleanly (With Live Completion Updates)

### Root Cause of the Current Subagent Problem
Right now, when a user asks the sidebar agent to use a subagent:
1. OpenCode V2's `subagent` tool **always runs subagents in the background**: it returns a child `sessionID` immediately, and the parent session receives a report when the child goes idle (often triggering a follow-up parent response summarizing the result).
2. Bionic Editor's current backend (`server/services/agent.ts`) spawns a **one-shot `opencode run --format json`** process bound to a single HTTP `POST /api/agent/chat` SSE request.
3. As soon as the parent finishes saying *"I started a subagent..."*, `opencode run` exits and the HTTP stream closes—so **when the background subagent finishes, the sidebar chat never receives the update**.

### Product Direction (Honest Terminology, Hidden Complexity)
- **Call them "Subagents" — do NOT oversell them as "experts" or "specialists"**: Calling an LLM prompt an "expert" creates false authority. Users already understand what an AI agent is; a **subagent** is simply a separate background agent task with fresh context that reports back when done.
- **Hide complexity unless the user asks for it**: Keep the main chat clean by default (a single compact status card per subagent run, plus an automatic follow-up message in chat when it finishes). Only show child session transcripts, prompts, or tool traces if the user clicks to expand them.
- **Use OpenCode's built-in subagents first (`explore` for read-only search/review, `general` for multi-step work)**: Avoid shipping fake "expert" persona prompts. If a workspace defines custom subagents in `.opencode/agents/*.md`, discover and expose them transparently by their configured name and description.

### Two Complementary UX Patterns (No Prompt Helpers)

#### Idea 1: Live Background Subagent Cards & Automatic Completion Updates *(Core — Directly Solves the Missing Update Bug)*
- Powered by the **Bionic-managed `opencode serve` + `@opencode/client` event bridge** (Phase 0 #4) pushing live OpenCode events (`experimental.job.updated`, `session.execution.*`, `session.text.delta`, `session.idle`) over Bionic's existing `/ws` WebSocket.
- **Default UI (Zero Clutter)**:
  - Whenever the agent launches a subagent (either automatically or because the user asked for one in chat), a compact, collapsed **`SubagentCard`** appears in the timeline:
    - Task description (from the `subagent` tool's `description`),
    - Agent type (`explore` read-only vs. `general` vs. workspace-defined agent name),
    - Live status (`Running · 18s` → `Completed` / `Failed` / `Cancelled`),
    - Inline **Stop** button while running (calls `POST /api/experimental/job/{id}/cancel`).
  - **Automatic Completion Delivery**: Even after the agent's initial turn ends and the user returns to editing their project root document, the card stays visibly `Running` (along with a subtle top/bottom pill *"1 subagent running in background…"* if scrolled away). The moment the subagent finishes:
    1. Its `SubagentCard` flips to `Completed` (with an optional subtle visual highlight / badge in the Agent Panel header if the user is focused on the editor), AND
    2. The parent agent's follow-up summary automatically streams into the sidebar chat and saves to the session—so the user immediately sees the outcome without ever having to ask *"is it done?"*.
  - **On-Demand Details**: Clicking **Show details** on a `SubagentCard` lazily fetches and displays the child subagent's output (and optional step trace via `GET /api/session/{childSessionID}/message`), keeping the main thread clean unless asked.
  - **Reconnect / Reload Resilience**: Reloading the browser tab re-hydrates active subagents from `GET /api/experimental/job` and any missed follow-up messages from `GET /api/session/{id}/message`.

#### Idea 2: Subtle "Subagents" Status Pill & Activity Drawer *(Paired with Idea 1)*
- **Invisible when unused**: Only appears in the Agent Panel header once at least one subagent has run in the current session (e.g., `Subagents · 1 running` or `Subagents (2)`).
- Clicking opens a lightweight popover/drawer listing active and recent subagent tasks in the session (description, status, elapsed time, **Cancel**, and **Inspect output**), letting users track multiple parallel subagents cleanly without scrolling back through chat history.

#### Clean Composer (Remove All Prompt Helpers)
- Do **not** add any "Run as Subagent" prompt helper chips, and **remove the existing canned `quickPrompts` bar** (`client/src/components/Agent/AgentPanel.tsx:84-88, 476-487`) so the chat composer stays clean and distraction-free. Users simply ask for what they want in plain English.

### Technical Implementation Plan
1. **OpenCode Server Event Bridge** — `server/services/opencodeServer.ts` (new, shared with Phase 0 #4):
   - Manage a private localhost `opencode serve` instance (`127.0.0.1`, ephemeral port) using `@opencode/client`.
   - Maintain a session-to-WebSocket mapping so `GET /api/event` pushes:
     - `experimental.job.updated` (`Job.Subagent`: `id`, `sessionID`, `parentSessionID`, `agent`, `description`, `status`, timestamps) → broadcast as `{ type: 'subagent_updated', ... }` over `/ws`.
     - Parent session follow-up turns (`session.execution.started`, `session.text.delta`, `session.tool.*`, `session.usage.recorded`, `session.idle`) → broadcast as `{ type: 'agent_event', sessionId, event }` over `/ws` and auto-persist to `.bionic/sessions/<id>.json` when `session.idle` fires!
   - Expose Bionic API routes on `apiRouter` (`server/index.ts`):
     - `GET /api/agent/subagents?sessionId=...` — lists active/recent subagent jobs for a session (`GET /api/experimental/job`) and available subagent definitions (`GET /api/agent`, filtered to `mode: 'subagent' | 'all'`).
     - `GET /api/agent/subagents/:childSessionId` — fetches child session messages/summary on demand (`GET /api/session/{childSessionId}/message`) when the user clicks **Show details**.
     - `POST /api/agent/subagents/:jobId/cancel` — cancels a running background subagent (`POST /api/experimental/job/{jobId}/cancel`).
     - `GET /api/agent/sessions/:id/sync` — reconciles Bionic's saved session with OpenCode's session state on reload/reconnect so completions that occurred while offline are never lost.
2. **Permission Guardrails for OpenCode V2**:
   - In `.opencode/opencode.jsonc` (managed safely with `jsonc-parser`), ensure explicit workspace safety rules deny reading `.env` / `.env.*` (`{ action: "read", resource: "*.env*", effect: "deny" }`) so auto-approved runs never leak API keys stored in `.env`.
3. **Frontend UI & Live WebSocket Sync**:
   - `client/src/types.ts`: Add `subagent` variant to `AgentTimelineItem` (`jobId`, `childSessionId`, `agent`, `description`, `status: 'running' | 'completed' | 'error' | 'cancelled'`, `startedAt`, `completedAt`, `summary?`).
   - `client/src/App.tsx`: Subscribe `/ws` to `subagent_updated` and `agent_event` messages so background subagent status changes AND follow-up parent assistant messages append live into the active chat session (even when `isStreaming` from the initial POST has ended!). Update `handleExportMarkdown()` (`REPORT.md` export) to include subagent runs cleanly.
   - `client/src/components/Agent/SubagentCard.tsx` (new): Collapsed-by-default card showing description, agent type (`explore` / `general` / custom), live elapsed timer while running, **Stop** button, and lazy-loaded **Show details** drawer.
   - `client/src/components/Agent/AgentPanel.tsx`: Render `SubagentCard`, display the subtle `Subagents` header pill only when subagents exist in the session, and collapse routine tool steps into a tidy expandable group when Coding Mode is OFF. Hide subagent controls cleanly when `harness !== 'opencode'`.

### Acceptance Criteria & Testing
- Asking the sidebar agent to *"launch a subagent to inspect X"* shows a live `Running` `SubagentCard`, allows the user to keep working while it runs, flips the card to `Completed` automatically when the subagent finishes, and automatically displays the parent agent's follow-up summary in the sidebar chat without manual refresh or follow-up prompting.
- Reloading the browser while a subagent is running (or right after it completes) still shows accurate subagent status and the completed follow-up message.
- Clicking **Stop** on a running `SubagentCard` cancels the child job on OpenCode (`POST /api/experimental/job/{id}/cancel`) and updates status to `Cancelled`.
- Clicking **Show details** loads the child subagent's output on demand; by default the child transcript stays hidden.
- Integration test (`tests/opencode-subagent-bridge.test.mjs`) verifies event mapping, `/ws` push delivery after initial turn completion, session persistence on `session.idle`, and graceful fallback when OpenCode is unavailable.

2. **Data Manifest Service (Performance & Security Hardened)** — `server/services/dataManifest.ts` (new):
   - **Concurrency & Atomicity**: Serialize all writes through an in-process async mutex and atomic temp-file-then-rename writes with `applyTargetOwnership()`, automatically regenerating `data/DATA_MANIFEST.md` on every write (and whenever `fileWatcher` detects external edits to `data/manifest.json`!).

     - Hash files using `crypto.createHash('sha256')` piped from `fs.createReadStream()` (constant memory).

     - **Git Repo Boundary Guard**: Before executing any Git command, verify `execFile('git', ['rev-parse', '--show-toplevel'], ...)` equals `fs.realpathSync(WORKSPACE_DIR)` (preventing accidental mutation of a parent Git repo when `WORKSPACE_DIR` is a nested folder!).

     - Detect tracked raw files via `git ls-files -- data/raw/`.

     - **Publication Leak Check (`web-report/`)**:
       1. Walk `web-report/` with `lstatSync()` and flag any symlink pointing to `data/raw/` or outside `WORKSPACE_DIR`.
       2. Pre-filter candidate files by **`sizeBytes > 0` matching a manifest entry's `sizeBytes`** before computing SHA-256 (avoids hashing unrelated report assets and eliminates empty-file `e3b0c442...` false positives).
       3. Also flag suspicious raw bioinformatics file extensions (`.fastq`, `.fq`, `.bam`, `.sam`, `.vcf`, `.h5ad`, `.loom`, `.bcf`) or oversized files (`> 25 MB`) inside `web-report/` so subsetted/compressed raw data leaks are also caught.
   - **No Arbitrary Shell `reacquire` Endpoint**: Deliberately **omit** `POST /api/data/manifest/:id/reacquire` from this plan (executing arbitrary shell commands from a Git-tracked JSON file over an unauthenticated CORS API is a supply-chain RCE and data-overwrite hazard).
